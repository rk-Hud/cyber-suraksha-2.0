## 1. Accessibility Commitment

CYBER SURAKSHA 2.0 is a student-led cybersecurity education and demonstration project focused on making digital safety information easier to understand and access.

We aim to make the website usable by people with different abilities, devices, languages and levels of technical knowledge.

Accessibility is an ongoing improvement goal. The application has not yet undergone a comprehensive independent accessibility audit, and full WCAG compliance is not claimed.

## 2. Priorities

Our accessibility priorities include:

- **Readable content:** Use clear headings, understandable instructions and readable text.
- **Keyboard accessibility:** Work toward making navigation, links, forms and interactive features usable without a mouse.
- **Screen-reader compatibility:** Use meaningful HTML structure and appropriate labels.
- **Visual accessibility:** Improve text contrast, layout clarity and visible keyboard focus.
- **Responsive design:** Support desktop, tablet and mobile screen sizes.
- **Multilingual access:** Provide cybersecurity awareness information in English, Hindi and Telugu where implemented.
- **Error clarity:** Make validation messages and instructions understandable.
- **Inclusive learning:** Explain cybersecurity concepts using beginner-friendly examples.

These are project priorities rather than a declaration that every requirement has already been verified.

## 3. Contributor Expectations

Contributors should:

1. Use semantic HTML elements.
2. Provide descriptive text for informative images.
3. Associate form fields with meaningful labels.
4. Avoid relying on colour alone to communicate information.
5. Maintain readable text contrast.
6. Ensure interactive elements have visible keyboard focus.
7. Test relevant features using keyboard navigation.
8. Keep instructions clear and easy to understand.
9. Preserve accessible behaviour when adding JavaScript interactions.
10. Document any known accessibility limitations.

Accessibility changes should be tested before they are merged into the main branch.

## 4. Reporting Accessibility Issues

Users and contributors can report accessibility barriers through GitHub Issues:

https://github.com/rk-Hud/cyber-suraksha-2.0/issues

When reporting a problem, include:

- The affected page or feature.
- A description of the accessibility barrier.
- The browser and operating system used.
- The assistive technology used, if relevant.
- Steps to reproduce the problem.
- The expected and actual behaviour.

Screenshots are optional.

**Privacy:** Do not include passwords, OTPs, financial details, identity documents, real victim reports or other sensitive information in public GitHub Issues.

For security vulnerabilities involving confidential information, follow the repository's `SECURITY.md` guidance instead.

## 5. Severity

Accessibility reports may be classified using the following suggested priorities:

| Severity | Description |
|---|---|
| Critical | A major function is inaccessible with no reasonable alternative |
| High | A significant barrier prevents important tasks |
| Medium | An accessibility issue makes a task difficult |
| Low | A minor usability or presentation improvement |

The project maintainer may adjust priorities after reviewing an issue.

## 6. How We Respond

Our intended process is to:

1. Review the submitted accessibility issue.
2. Attempt to reproduce the reported problem.
3. Assess the severity and affected functionality.
4. Identify a suitable correction or workaround.
5. Test the proposed improvement.
6. Document the change in GitHub.

Response times are not guaranteed because this is a student-maintained project.

## 8. Supported Environments

The application is designed as a browser-based web application.

Its intended environments include:

- Windows desktop and laptop browsers.
- Modern mobile browsers.
- Common keyboard and mouse input.
- Responsive layouts across different screen sizes.

The project has been demonstrated in a desktop browser and deployed through Render.

Compatibility with every browser, device, screen reader and assistive technology has not yet been independently verified.

## 9. Known Limitations

Current limitations include:

- No comprehensive WCAG accessibility audit has been completed.
- Screen-reader compatibility has not been fully verified.
- Keyboard navigation across every interactive feature requires additional testing.
- Some interface elements or translations may need accessibility improvements.
- Hindi and Telugu support may not cover every page or feature.
- Free hosting may cause a delay when the website starts after inactivity.

These limitations are recorded to support transparent and continuous improvement.

The public website is an educational, read-only demonstration using synthetic examples. It does not submit official cybercrime complaints or provide live government, police or banking responses.

## 10. Feedback and Improvements

Accessibility feedback is welcome through the repository's GitHub Issues section.

Future improvements may include:

- Expanded keyboard-navigation testing.
- Screen-reader testing.
- Improved contrast and focus indicators.
- Better mobile accessibility.
- More consistent multilingual support.
- Clearer form instructions and validation messages.
- Accessibility regression tests.

## 11. Accessibility Standards

The project uses the Web Content Accessibility Guidelines (WCAG) as a reference for future accessibility improvements.

Official reference: https://www.w3.org/WAI/standards-guidelines/wcag/

**Compliance statement:** CYBER SURAKSHA 2.0 does not currently claim independently verified WCAG 2.2 Level A, AA or AAA conformance.
